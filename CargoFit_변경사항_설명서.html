기존 적재 시뮬레이터 대비 이번에 바뀐 내용 정리
대상: 팀원 · 작성일: 2026-09-15 · 저장소: github.com/Mir-yong/cargo-fit
3줄 요약
  1. 최적화 엔진에 물리 제약 4종(파손주의·최대 적재 단수·지지율·무게중심)이 추가되고 화면에서 설정 가능해졌습니다.

  3. 웹에 배포했습니다. 설치 없이 링크만으로 결과를 볼 수 있습니다.

1 먼저 확인할 것 — 기존과 달라지는 점

아래 두 가지는 기존에 쓰던 데이터·결과와 직접 충돌할 수 있으니 반드시 먼저 읽어주세요.

① 같은 하역지에 priority가 섞인 CSV는 업로드가 거부됩니다

목적지별 LIFO(후입선출) 검증을 위해, 같은 destination은 모두 같은 priority를 가져야 한다는 규칙이 업로드 시점에 강제됩니다. 어긋나면 400 에러와 함께 어느 목적지가 문제인지 알려줍니다.

확인 결과 기존 벤치마크 CSV 5종(BR1·BR2·BR4·BR6·BR7)은 전부 이 규칙을 이미 만족하므로 그대로 쓰시면 됩니다. 직접 만든 CSV만 확인이 필요합니다.

② 최소 지지율 기본값이 70% → 80%로 올라갔습니다

같은 CSV·같은 조건이라도 이전보다 용적률이 낮게 나올 수 있습니다. 더 보수적으로(안정적으로) 쌓기 때문입니다. 예전 수치와 비교할 일이 있으면 좌측 고급 설정에서 지지율을 70%로 내리고 돌리면 됩니다.

3 최적화 엔진 변경 — 물리 제약 4종

기존에는 코드에 숫자가 박혀 있던 제약들을 화면에서 조절할 수 있게 하고, 없던 제약을 새로 넣었습니다. 좌측 패널 고급 설정에서 조정합니다.

제약이전지금
파손주의
(fragile)		 없음. stackable 하나로만 구분 CSV에 fragile 컬럼(0/1) 추가 인식. 1이면 그 위에 아무것도 쌓지 않습니다. 컬럼이 없는 기존 CSV는 전부 0으로 처리되어 동작이 바뀌지 않습니다.
최대 적재 단수 제한 없음 N단까지만 쌓도록 제한할 수 있습니다. 기본값은 "제한 없음"이라 켜지 않으면 기존과 동일합니다. 각 화물이 몇 단째인지도 결과에 기록됩니다.
최소 지지율 0.70 하드코딩 50~95% 조절 가능. 기본값 80% (1절 ② 참고)
무게중심 허용오차 0.05 하드코딩
(정밀·현장 두 곳에 따로 박혀 있었음)		 0~15% 조절 가능. 두 경로가 같은 설정값을 쓰도록 통일했습니다.

목적지별 LIFO 검증

"이 적재안으로 실제 하역이 순서대로 되는가"를 판정해 결과에 표시합니다.

  • 업로드 시점: 목적지 ↔ priority 정합성 검사 (1절 ① 참고)
  • 결과 화면: 검토 필요 패널에 "LIFO 재배치 필요 · 화물 N개"와 목적지별 내역("B 목적지 35개 · C 목적지 14개")을 표시
설계 메모 — 왜 기존 코드가 거의 안 바뀌었나

새 설정값들을 함수 인자로 10여 개 함수에 전부 추가하는 대신, 이미 모든 배치·평가 함수에 전달되고 있던 Container 객체의 필드로 넣었습니다. 덕분에 nsga2.py · heuristic.py · solutions.py의 호출부는 한 줄도 수정하지 않았고, 회귀 위험을 최소화했습니다.

작업 중 발견해 고친 버그

최대 적재 단수에 off-by-one이 있었습니다. "2단 제한"인데 3단까지 쌓였습니다 (level > max → level >= max). 단위 테스트로 잡아 수정했습니다.

4 화면 — 전면 재설계

가장 큰 변화입니다. "기능이 많아 뭘 봐야 할지 모르겠다"는 문제를 정보 구조 차원에서 다시 짰습니다.

영역이전지금
업로드 화면 좁은 좌측 사이드바 안에 업로드 영역. 나머지 화면은 비어 있음 화면 중앙 전체를 쓰는 전용 시작 화면. 업로드하면 작업 화면으로 전환
단계 이동 상단 표시만. 클릭 불가 클릭해서 이동. 선행 데이터가 없으면 잠깁니다(CSV 없으면 02, 결과 없으면 03)
적재안 선택 큰 카드 3개 한 줄 세그먼트 컨트롤. 선택된 것만 강조
결과 패널 같은 크기 카드 5개(용적률·재작업·무게중심·지지율·중량)가 나열 적재 품질 하나를 크게 + 문제는 검토 필요 패널로 분리 + 나머지는 작은 목록. 문제 없으면 "검토할 문제가 없습니다"로 표시
3D 뷰 조작 우측 세로 버튼 5개(ISO/SIDE/TOP/DOOR/전체화면) 상단 세그먼트 [3D][TOP][SIDE][DOOR] + 우하단에 Fit·Reset·전체화면 작게
가중치 조정 항상 펼쳐져 있음 기본 접힘. 필요할 때만 펼침(적용 여부는 배지로 항상 표시)
화물 선택 없음 3D에서 화물을 클릭하면 하역지·치수·중량·적재 단수·순서를 보여주는 상세 카드
계산 버튼 누르면 상태 변화 없음 "계산 중…" 상태 + 중복 클릭 방지 + 실패 시 에러 표시
02 단계 중앙이 빈 화면 선택한 컨테이너를 3D로 미리 보여줌(규격 바꾸면 즉시 반영)

그 외: 화물 목록 검색, CSV 템플릿 다운로드, 고급 설정 접기, 브랜드 아이콘 적용.

5 3D 시각화 — 새로 만들었습니다

단순 육면체 + 원색이던 화물을 다시 설계했습니다. 적재 좌표·치수 계산은 전혀 건드리지 않았고 보여주는 층만 바꿨습니다.

  • 형태 — 모서리를 다듬은(bevel) 지오메트리. 규격별로 캐시해 화물 100여 개도 가볍게 처리
  • 색 — 채도 낮은 파스텔 7색. 하역지 A~G에 고정 매핑되어 매번 색이 바뀌지 않습니다
  • 입체감 — 윗면/앞면/옆면 밝기를 형상에 구워 넣어(vertex color) 조명과 무관하게 항상 면이 구분됩니다
  • 그림자 — 바닥에 부드러운 그림자가 생겨 화물이 "놓여 있는" 느낌이 납니다
  • 컨테이너 — 선으로만 그리던 것을 반투명 공간으로. 카메라 쪽 벽은 자동으로 비쳐 항상 내부가 보입니다
  • 라벨 — 표면에 글자를 인쇄하는 대신 작은 라벨판을 얹었습니다(큰 화물·선택된 화물만)
  • 카메라 — 컨테이너 8개 꼭짓점을 실제로 투영해 맞추므로 어떤 규격·창 크기에서도 잘리지 않습니다
작업 중 발견해 고친 문제 3가지
  1. 화면 전체가 어두웠던 원인 — Three.js r155부터 조명 계산이 바뀌어 모든 광원 세기에 1/π(약 0.318)가 곱해집니다. 기존 감각으로 넣은 값이 3배 이상 어두워지고 있었습니다. 보정 후 실측으로 값을 다시 잡았습니다.
  2. 바닥이 통째로 잿빛 — 그림자 계산 범위 밖이 전부 그늘로 처리되는 현상. 범위를 바닥 크기에 맞춰 해결
  3. 라벨 글자가 뒤집힘 — 평면을 눕히며 글자 방향이 카메라 쪽을 향했던 문제

8 검증

자동 검사 39개 전부 통과

"눌러도 아무 일 없는 버튼"이 없는지 실제 브라우저를 띄워 확인합니다. 뷰 전환·Fit·Reset·휠 줌·드래그 회전은 렌더 결과를 해시로 비교해 카메라가 실제로 움직였는지 확인하고, 재생·배속·타임라인·적재안 전환·가중치 슬라이더는 실제 값 변화로 확인합니다. JS 에러 0건.

추가로 가중치 슬라이더는 서버(Python)와 화면(JS)이 1001개 지점에서 완전히 같은 해를 고르는지 교차 검증했고, 물리 제약 4종은 단위 테스트로 확인했습니다.

9 알려진 제약

  • 공개 데모 페이지는 미리 계산된 결과만 봅니다. 새 CSV 계산·가중치 조정·명세서 PDF는 내 컴퓨터에서 서버를 띄워야 합니다.
  • 명세서 PDF는 wkhtmltopdf가 설치돼 있어야 합니다(맥 기본 미설치).
  • 오프라인 불가 — 3D 라이브러리와 폰트를 CDN에서 받습니다.
  • 계산 중 취소 기능이 없습니다. 브라우저를 닫아도 서버에서 계산은 계속 돕니다. 여러 번 돌렸다면 서버를 재시작해야 CPU가 정리됩니다.
  • START.md · README.md는 아직 옛 내용입니다(경로·사용 순서·"의존성 없음" 문구). 이 문서를 기준으로 봐 주세요.
